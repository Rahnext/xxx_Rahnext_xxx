5. شروع درخواست جدید

• روبیکا

«فاکتور شما کپی شد. لطفاً فاکتور کپی‌شده را در چت پشتیبانی Paste کرده و ارسال کنید. تیم پشتیبانی راهنکس در اسرع وقت به درخواست شما پاسخ خواهد داد.»

۱۱. ذخیره‌سازی و محدودیت‌های نسخه وب
این پروژه برای انتشار اولیه روی GitHub Pages در نظر گرفته شده است.
در نتیجه نسخه اولیه باید بدون نیاز به سرور مستقل و بدون نیاز به ربات تلگرام کار کند.
الزامات
• اطلاعات فرم با localStorage ذخیره شوند.
• با Refresh صفحه، اطلاعات واردشده از بین نروند.
• کاربر بتواند فرایند نیمه‌تمام را ادامه دهد.
• امکان حذف کامل اطلاعات ذخیره‌شده در مرورگر وجود داشته باشد.
• فاکتور درخواست به‌صورت محلی ساخته شود.
• هیچ اطلاعاتی بدون اقدام آگاهانه کاربر ارسال نشود.
نکته:
GitHub Pages به‌تنهایی پایگاه داده مرکزی یا سیستم احراز هویت مشترک ایجاد نمی‌کند.
بنابراین در نسخه اولیه:
• ثبت درخواست به معنی ثبت مرکزی در سامانه نیست.
• اطلاعات به‌صورت خودکار به مدیر منتقل نمی‌شوند.
• تأیید رزرو فقط پس از ارسال اطلاعات به پشتیبانی انجام می‌شود.
ساختار کد را طوری طراحی کن که در آینده امکان افزودن Backend و پایگاه داده مرکزی وجود داشته باشد.
تمام داده‌های کاربر در localStorage با یک کلید مشخص (مثلاً rahnext_form_data) ذخیره شوند و در بارگذاری مجدد بازیابی شوند.

۱۵. ساختار پیشنهادی فایل
برای نسخه اولیه ترجیحاً تمام پروژه را در یک فایل index.html تحویل بده.
CSS داخل تگ Style و JavaScript داخل تگ Script باشد.
اگر برای نظم بهتر نیاز به فایل‌های جداگانه داری، ساختار پوشه را نیز مشخص کن؛ ولی نسخه تک‌فایلی باید قابل اجرا باشد.
کد باید:
• کامل باشد.
• به‌صورت مستقیم اجرا شود.
• خطای JavaScript نداشته باشد.
• با مرورگرهای متداول سازگار باشد.
• برای GitHub Pages آماده باشد.
• بدون نصب وابستگی اضافی اجرا شود.
تمام متن‌ها فارسی و راست‌چین باشند، به‌جز نام برند و اصطلاحات فنی.
